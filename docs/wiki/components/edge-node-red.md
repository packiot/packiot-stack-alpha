# edge-node-red

> **Layer 3 · Components** — the Node-RED pieces of the edge: the **legacy** `edge-node-red`
> submodule (factory Node-RED of the old platform, retired on staging) and the **new**
> generated per-client *reader flow* that runs in a PLC-capable Node-RED on a client box. For
> engineers who meet "Node-RED" on a box or in the repo and need to know which one it is.
> Up: [Edge subsystem](../subsystems/edge.md)

## Responsibility

There are two different things called "edge Node-RED". Keep them apart:

| | Legacy `edge-node-red` (submodule) | New generated reader flow |
|---|---|---|
| Accountable for | Old factory edge: SparkPlug-style JSON to RabbitMQ, operator HTTP API, GraphQL polling of Hasura | Reading PLCs and POSTing raw tags to the local sparkplug-agent — nothing else |
| Source | `edge-node-red/` (git submodule, branch `staging`) | Generated by `onboard-gen` artifact 6 `<tenant>-reader-flow.json` (`internal/agent/clientdescriptor/generate_reader.go`) |
| Image | `edge-node-red/Dockerfile` (`nodered/node-red:4.0.9-20`) | `docs/clients/edge-deployment/Dockerfile.nodered-reader` (`nodered/node-red:4.0` + baked `node-red-contrib-s7@3.1.3`, `-modbus@5.45.0`, `-opcua@0.2.354`) |
| Status | **Legacy.** Staging service `edge-nodered` gated behind profile `legacy-sim` since 2026-08-16; excluded from production compose | **Current** option for clients on the Node-RED connectivity path (profile `nodered` in the edge bundle) |

**Generated reader flow**

| | |
|---|---|

## Inputs & outputs

### Legacy flows (`edge-node-red/flows/*.json`)

| Tab | Inputs | Outputs |
|---|---|---|
| `Sparkplug` | `POST /plc-data` (http in, "PLC Inject (Simulator / E2E)"), link from Configuration | `pack-queue` → function "Publish: oee (amqplib)": RabbitMQ exchange `oee`, routing key `sparkplug.data.<first metric segment, lower-cased>`; Loki push `http://loki:3100/loki/api/v1/push` |
| `API` | 20 `http in` endpoints for the old operator (`/session`, `/start-po`, `/change-po`, `/replace-po`, `/create-start`, `/set-event`, `/split-events`, `/add-manual-event`, `/edit-manual-event`, `/machines/:lineId`, `/production`, `/pending-events`, …) | edge-api calls with `API_KEY` + `ID_ENTERPRISE`: `/api/production-orders/{setup,start,replace,create-and-start}`, `/api/downtimes/{justify,split,create-manual-event,edit-manual-event}` on `EDGE_API_BASE_URL` |
| `GraphQL` | Timers: login every 21,600 s, token refresh 3,000 s, PO data every 300 s | Firebase `identitytoolkit` / `securetoken`, Hasura queries (language packs, events, shift hours, downtime reasons, PO list) |
| `Configuration` | Inject at start | Global context: enterprise settings, packml topic configuration, device/language |
| `PLCs` | One example `s7 in` node | PLC status into global `healthData` |
| `Health Data and Ping` | Timer 60 s | Host load/drives/uptime/memory into health data |
| `Publish to edge.plc-normalized` | link `plc-normalized.in` | RabbitMQ HTTP management API publish to exchange `edge.plc-normalized`, key `edge.plc-normalized.<tenant>` |

### Generated reader flow

```text
 [s7 in / modbus-read / opcua nodes]  (poll defaults: S7 15 s, Modbus 15 s, OPC-UA 10 s)
        │ one per endpoint; host from env PLC_HOST_<NAME>
        ▼
 [normalize function]  metric = canonical SUFFIX (packml_topic + leaf − canonical prefix)
        ▼
 [http request] POST {endpoint, scan_ts, tags[]}  X-Ingest-Key  → sparkplug-agent:9104/v1/tags
        └─ optional 2nd branch (StagingTee): POST to <TENANT>_STAGING_TEE_URL with
           <TENANT>_STAGING_TEE_KEY; inert until both env vars are set
 [<tenant> customizations] tab: descriptor-sourced integration nodes; never rewritten
                                by regeneration of the reader tab
```

## Internal design

**Legacy image boot** (`edge-node-red/entrypoint.sh`): optionally loads env from Secrets
Manager (`AWS_SECRET_ID`), refuses to start unless `NODE_RED_CREDENTIAL_SECRET`,
`RABBITMQ_HOST`, `RABBITMQ_USER`, `RABBITMQ_PASSWORD`, `ID_PUBSUB_NODE`, `API_KEY`,
`FIREBASE_API_KEY`, `HASURA_URL` are set, then copies the flow files from `/repo-data` into
`/data` on **every** start (so the image, not the volume, owns the flows) and deletes stale
per-tab files. Flows are loaded through FlowManager from split `flows/*.json`; `flows.json`
and the split files must be edited together.

**Why the legacy path is retired on staging** (from `compose.staging.yml`): the new stack
ingests through sparkplug-decoder and serves the operator through edge-api + read-api; the
Python simulator's `/plc-data` posts were double-encoded by `pack-queue` and dropped by the
consumer's poison guard; Hasura was retired (2026-08-21). The legacy image is still the
factory Node-RED of the **legacy production platform** for clients not yet migrated (built by
the submodule's `build.yml` to Docker Hub `devpackiot/edge-node-red` and shipped by
self-hosted runners, per its README). That deploy path is outside this repo's compose files.

**Generated reader flow** node ids are deterministic (tenant + protocol + endpoint index), so
regenerating the same descriptor produces a byte-stable diff. The same descriptor `plc:` block
also drives the Go readers' `client.yaml`, so a tenant can pick Node-RED *or* the Go readers
and both emit identical suffixes.

## Configuration

**Legacy (staging service, profile `legacy-sim`)**

| Env | Staging value | Effect |
|---|---|---|
| `RABBITMQ_HOST` / `_USER` / `_PASSWORD` | `rabbitmq` / from `.env` | AMQP publish |
| `ID_PUBSUB_NODE` | `staging-app-ec2` | Node identity |
| `HASURA_URL`, `HASURA_ADMIN_SECRET` | `http://hasura:8080/v1/graphql` (Hasura retired) | GraphQL tab |
| `API_KEY` | `${EDGE_API_KEY}` | Sent to edge-api |
| `EDGE_API_BASE_URL` | `http://edge-api:8080` | API tab target |
| `ID_ENTERPRISE` | `3` | Scopes the unscoped entities query to CPACK-Staging |
| `FIREBASE_API_KEY` | placeholder | Required by the entrypoint guard |
| `JWT_SECRET` | via `env_file: .env` (not set explicitly) | Read by the API tab's "Check Credential and Generate JWT" for `/session` |
| `STAGING_MQ_*` (submodule compose) | unset | Optional parallel forward to staging RabbitMQ |

**Generated reader flow** (via the bundle `.env`, passed with `env_file`)

| Env | Effect |
|---|---|
| `AGENT_INGEST_API_KEY` | Required; sent as `X-Ingest-Key` |
| `PLC_HOST_<NAME>` | Per-endpoint PLC host |
| `<TENANT>_AGENT_URL` | Override of `http://sparkplug-agent:9104/v1/tags` |
| `<TENANT>_STAGING_TEE_URL` + `<TENANT>_STAGING_TEE_KEY` | Enable the optional staging tee branch |
| `NODERED_READER_FLOW`, `NODERED_IMAGE`, `NODERED_UI_PORT` | Seed file, image, editor port |

## Data & invariants

- The reader flow must **not** publish `spBv1.0/*`; the agent owns that namespace (ADR-0042).
- First-boot seeding only: after that, `/data/flows.json` belongs to Node-RED, so UI edits and
  customizations persist; a regenerated reader tab must be re-imported deliberately.
- The legacy image, in contrast, overwrites `/data` flows on every start.

## Observability

- Node-RED editor on `:1880` (on client boxes reach it only through SSM port-forward /
  csadmin web UI; see [edge-session-broker](edge-session-broker.md)). For twin tenants the
  proxy rejects `POST|PUT|DELETE|PATCH` on `/flows`, `/flow`, `/nodes`, `/context`, `/inject`
  (read-only editor).
- Legacy: Loki stream `{source="edge-nodered"}` with `debug_point` labels; `GET /health`.
- Reader flow: the agent's `sparkplug_agent_http_ingest_total` and unmapped counters are the
  real signal.

## Failure modes

| Failure | Symptom | Cause | Fix |
|---|---|---|---|
| Reader flow never starts on a fresh box | "missing types" for s7/modbus/opcua nodes | Vanilla Node-RED image without palettes, no npm egress | Use `Dockerfile.nodered-reader` (palettes baked) |
| Seed skipped | Default empty flow | Checking for a missing `flows.json` fails because the image ships one | The entrypoint uses the `.reader-seeded` sentinel |
| Agent logs `accepted:0` | Nothing mapped | Compose cannot interpolate an env *key* like `${TENANT_UPPER}_INGEST_KEY`, so the flow had no key / wrong suffixes | Use the fixed `AGENT_INGEST_API_KEY` name; regenerate reader + agent together |
| POST from Node-RED to `localhost:9104` refused | Connection refused | `localhost` inside the Node-RED container is not the agent | Use the service name `sparkplug-agent` (generator default) |
| Node-RED editor unusable on sim boxes (2026-09-16) | Image extraction fails | dind sim boxes cannot extract the Node-RED image (overlay whiteouts) | Use a real VM / non-dind box |
| Legacy duplicated tabs | Tab IDs registered twice | Renamed tab file left in the volume (bug 206) | Entrypoint deletes stale per-tab files |

## Operating it

- **Bundle with Node-RED:** `docker compose --profile nodered -f compose.edge.yml --env-file
  .env up -d`.
- **Legacy on staging (only if needed):** `COMPOSE_PROFILES=legacy-sim docker compose -f
  compose.staging.yml up -d edge-nodered`. It points at retired Hasura and will log errors.
- **Safe:** restarting a reader-flow Node-RED (stateless reads). **Unsafe:** editing the
  reader tab on the box (lost on the next regeneration) — put custom logic on the
  customizations tab or in the descriptor.

## Tests

- `go test ./internal/agent/clientdescriptor/...` in `services/sparkplug-decoder` (reader-flow
  generation, reader contract).
- Legacy submodule: no automated flow tests in this repo; `make up` runs it standalone.
