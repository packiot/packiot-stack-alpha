# Edge box (factory box, on-prem offline, edge-operator)

> **Layer 3 · Components** — the client's factory machine: how it is enrolled in AWS SSM, what
> edge-api pushes onto it, the thin reader, the optional on-prem offline stack (ADR-0053) and
> the edge-operator (ADR-0054). Replaces the old wiki pages 11 and 12, re-verified against code.
> For CS engineers and developers who deploy to or debug a client box.
> Up: [Edge subsystem](../subsystems/edge.md)

## Responsibility

The edge box is accountable for **getting a factory's PLC readings to the cloud reliably, with
zero inbound firewall holes**, and — when the tenant opts in — for keeping the floor able to
*see* (dashboard) and *operate* (operator SPA) during an internet outage. Everything that runs
on it is generated by onboarding (edge-api / `onboard-gen`) and pushed through AWS SSM; nothing
should be hand-edited on the box.

## At a glance

| | |
|---|---|
| Hardware | Client-owned Linux box (Debian/Ubuntu), Docker + compose plugin |
| Control plane | AWS SSM **hybrid managed instance** (`mi-…`), `amazon-ssm-agent`, outbound 443 only |
| Enrolment tags | `enterprise=<id_enterprise>`, `managed-by=packiot-edge-api` (set by edge-api `CreateActivation`) |
| Reader bundle dir | `/opt/packiot` (`SSM_EDGE_DEPLOY_DIR`), compose `compose.edge.yml` |
| On-prem stack dir | `/opt/packiot/fatedge` (`SSM_ONPREM_DEPLOY_DIR`), compose `compose.onprem-edge.yml`, env `.env.onprem` |
| Egress | HTTPS to `ingest.<env>.packiot.app` (thin reader) or mTLS `:8883` (Mode-B agent) |
| Managed by | [edge-api](edge-api.md) `EdgeSsmService` (`/api/edge-ssm/*`, CS-Admin only), [csadmin](csadmin.md) "Box Ops" UI |
| Known boxes | Bispharma box (`mi-0114…`, noted 2026-09-22); CPACK factory box runs a Mode-B bundle (`edge-cpack-nodered` + `edge-cpack-agent`, noted 2026-08-19). Box ids are operational facts; check AWS before relying on them |

## Inputs & outputs

| Box shape | In | Out |
|---|---|---|
| Thin reader (edge-api Go-live default) | PLCs (Modbus TCP, S7) | `POST <INGEST_URL>` with `X-Ingest-Key` → cloud `sparkplug-agent-shared`; optional best-effort copy to `http://127.0.0.1:9104/v1/tags` |
| Mode-B bundle (`docs/clients/edge-deployment/compose.edge.yml`) | PLCs via Go readers or Node-RED reader flow | SparkPlug B over mTLS to `ssl://ingest.prod.packiot.app:8883`, cert CN = tenant |
| On-prem offline add-on | The reader's best-effort tee | Floor dashboard `:${DASHBOARD_PORT}`, local SQLite current state (never sent to cloud) |
| Edge-operator add-on | Operator tablets on the LAN | `/api`, `/session` → `EDGE_API_UPSTREAM`; `/v1` → `REFDATA_UPSTREAM` (cached) |

## Internal design

### Enrolment (SSM hybrid activation)

```text
 csadmin ──POST /api/edge-ssm/activation {idEnterprise}──► edge-api
   edge-api ──ssm:CreateActivation(IamRole=SSM_HYBRID_INSTANCE_ROLE, RegistrationLimit=1,
              DefaultInstanceName=enterprise-<id>, Tags enterprise/managed-by,
              expiry SSM_ACTIVATION_WINDOW_HOURS=24h)──► AWS
   ◄── activationId + activationCode (shown ONCE, never logged)
 box: /opt/packiot/edge-ssm.env (SSM_ACTIVATION_CODE/ID/REGION)
      ssm-register.service (systemd oneshot) → ssm-register.sh
        installs amazon-ssm-agent, `amazon-ssm-agent -register …`, idempotent
        (skips if /var/lib/amazon/ssm/registration exists)
 box now appears as mi-… with the activation's tags
```

- The edge-api IAM policy scopes `ssm:SendCommand` / `ssm:StartSession` to resources tagged
  `managed-by=packiot-edge-api`, so edge-api can never command the pre-existing `i-…` EC2
  fleet. A plain EC2 box therefore gets `StartSession` **denied**: make test boxes hybrid
  (`mi-`) with an activation, like a real factory box.
- The comment in `ssm-register.sh` says the box is tagged `client=<slug>`; the tags actually
  come from `CreateActivation` in edge-api (`enterprise`, `managed-by`).
- edge-api authenticates to AWS only through its EC2 instance role (no static keys). Empty
  `SSM_HYBRID_INSTANCE_ROLE` ⇒ every edge-ssm endpoint returns 503.

### Box Ops endpoints (`edge-api/src/usecases/edge-ssm/edge-ssm.controller.ts`)

| Endpoint | What runs on the box |
|---|---|
| `POST activation` | (AWS only) mint activation |
| `GET status`, `GET status/detailed` | SSM ping + a detailed script (containers, health) |
| `POST bootstrap` | Install Docker via `get.docker.com` if absent, then the deploy command |
| `POST deploy` | `cd /opt/packiot && docker compose -f compose.edge.yml up -d --force-recreate` (override: `SSM_EDGE_DEPLOY_COMMAND`) |
| `POST deploy-bundle` | Generate reader bundle from the stored descriptor, base64-write files, deploy; if `descriptor.onprem_offline` also run `deploy-onprem` |
| `POST deploy-onprem` | Write generated `compose.onprem-edge.yml` + `.env.onprem`, `docker compose … up -d --build` in `/opt/packiot/fatedge` (400 unless `onprem_offline=true`) |
| `POST apply-agent-config` | Targets the **staging app box** (`SSM_SHARED_AGENT_INSTANCE_ID`), not the factory: writes `docs/clients/tenants/<t>.yaml`, `--profile shared-tee up -d --force-recreate --no-deps sparkplug-agent-shared` |
| `GET deploy/:commandId`, `GET command/:commandId` | Poll RunCommand results |
| `GET health` | `curl http://localhost:9103/healthz` on the box (`SSM_HEALTHZ_URL`) |
| `POST restart`, `GET logs` | `docker compose restart [svc]`, `logs --tail=N svc` |
| `GET connect` | Copy-paste `aws ssm start-session` commands (engineer's own IAM identity) |
| `POST session`, `DELETE session/:id`, `POST webui` | Brokered browser shell / web UI, see [edge-session-broker](edge-session-broker.md) |
| `POST deregister` | Deregister the managed instance |

All scripts are fixed server-side templates; the only caller-influenced content is a
single-quoted base64 blob. **Twin tenants** (any id ≥ 2,000,000, plus
`SSM_SANDBOX_ENTERPRISE_IDS`, default `2000003`) get every mutating op *mocked*: a
success-shaped `mock:true` response with the `wouldRun` command, nothing sent. Reads stay real.

### The thin reader (`packiot-edge-reader`)

Generated by `edge-api/src/usecases/edge-ssm/shared/reader-bundle.ts` from the descriptor's
`plc:` block. Files written to `/opt/packiot`:

| File | Content |
|---|---|
| `compose.edge.yml` | One service `reader`, container `packiot-edge-reader`, image `${READER_IMAGE:-python:3.12-slim}`, `restart: unless-stopped`, log cap 10 MB × 3. `network_mode: host` when the tenant is on-prem-offline |
| `reader.py` | Fixed script: Modbus via `pymodbus==3.6.9`, S7 via `python-snap7==2.0` (pip-installed at start; S7 endpoints are skipped with a log if libsnap7 is missing on the slim image) |
| `reader.config.json` | `group`, `poll_interval_sec` (default 5), `targets[]`, `endpoints[]` with **pre-computed metric suffixes** |
| `.env` | `INGEST_URL`, `GROUP`, `INGEST_KEY`, `PLC_HOST_<NAME>` for `secret://` hosts, plus `AGENT_INGEST_API_KEY` when on-prem. **Written only if absent** so a hand-seeded key survives re-deploys |
| `README.md` | Generation gaps (unsupported protocol, missing tag map) |

Reader behaviour:

- Each poll POSTs `{group, endpoint, scan_ts, tags:[{metric, value, ts}]}` with
  `X-Ingest-Key`. The metric is the suffix `packml_topic + leaf − canonical.prefix`,
  computed at generation time (the "F6" keying bug cannot recur on the box).
- `targets[0]` is the **primary** cloud sink: retried in-line, then spooled to
  `/var/lib/packiot/spool` (host `./spool`) with its original `scan_ts`; replayed oldest-first
  when the link returns; capped at 20,000 files (oldest dropped). A 4xx is "drop" (never
  spooled).
- A **best-effort** target (on-prem tee, `http://127.0.0.1:9104/v1/tags`) gets one short
  attempt, is never retried or spooled, and its failures are logged and ignored.
- DNS answers are cached for 300 s and the last good answer is reused through resolver
  blips (flaky factory DNS returned `EAI_NODATA`).

Default ingest URL: `SSM_EDGE_INGEST_URL` = `https://ingest.prod.packiot.app:8449/v1/tags`;
staging overrides it to `https://ingest.staging.packiot.app:8449/v1/tags`.

!!! warning "Unverified"
    Neither `compose.production.yml` nor `terraform/production` defines an `:8449` front-door
    or a shared agent; production factory traffic enters on mosquitto `:8883` (mTLS). A box
    Go-lived against edge-api's production default would post to an endpoint not defined in
    this repo. Confirm before a production Go-live.

### On-prem offline stack (ADR-0053 "B-minimal", visibility)

Opt-in per tenant with `client_descriptors.descriptor.onprem_offline = true`
(`GET/POST /api/onboarding/onprem-offline`, audit event `onboarding.onprem-offline`).

```text
 PLC ─► packiot-edge-reader ─┬─► cloud shared agent (HTTPS)          PRIMARY, spooled
       (network_mode: host)  └─► 127.0.0.1:9104  onprem-agent         best-effort tee
                                      │ SparkPlug B (uplink = tcp://mosquitto:1883)
                                      ▼
                               onprem-mosquitto
                                      ▼
                        onprem-transformer (LOCAL_DECODE_ONLY=true)
                                      │ UPSERT current_state
                                      ▼
                     edge_localstate volume: current-state.db (SQLite)
                                      ▼
                         onprem-dashboard :${DASHBOARD_PORT} ◄── floor browser
```

| Container | Image / entrypoint | Key env | Limits |
|---|---|---|---|
| `onprem-mosquitto` | `eclipse-mosquitto:2`, `init: true` | config `./configs/mosquitto/mosquitto.conf` | — |
| `onprem-agent` | `packiot-sparkplug-decoder:local` built on the box from `./services/sparkplug-decoder`; `sparkplug-agent --config /etc/packiot/agent.yaml` | `AGENT_HTTP_INGEST_ENABLED=true`, `AGENT_INGEST_PORT=9104` (published `127.0.0.1:9104`), `AGENT_INGEST_API_KEY` (required), `AGENT_BIRTH_ALL_MAPPED=true`, `MQTT_STALE_THRESHOLD_SECONDS=-1` | 128 MB, 0.25 CPU |
| `onprem-transformer` | same image, `sparkplug-decoder` | `EDGE_TRANSFORMER_MODE=factory`, `MQTT_BROKER_URL=tcp://mosquitto:1883`, `AMQP_SOURCE_ENABLED=false`, `LOCAL_DECODE_ONLY=true`, `LOCAL_STATE_DB=/var/lib/edge-transformer/current-state.db`, `PHASE9_LINE_AGG_ENABLED=true`, `CLIENT_YAML_PATH=/etc/packiot/client.yaml` | 192 MB, 0.5 CPU |
| `onprem-dashboard` | same image, `edge-dashboard` | `LOCAL_STATE_DB`, `TENANT` (required), `DASHBOARD_PORT=8080` in-container, `DASHBOARD_STALE_SECONDS` (default 30) | 64 MB, 0.25 CPU |

- `LOCAL_DECODE_ONLY=true` makes the transformer skip the AMQP publisher and outbox
  (`cmd/edge-transformer/main.go` ≈ line 534): the box opens no cloud socket from this stack.
  The cloud keeps receiving this tenant's data through the reader's primary target.
- `internal/localstate` keeps one row per `(tenant, source, metric)`: a conditional UPSERT
  that only overwrites when the incoming `ts_millis` is newer. `source` is the SparkPlug
  publisher (`GROUP/EDGE/DEVICE`); there is no `id_equipment` on the box.
- The dashboard serves `/` (self-contained HTML, no external assets), `/api/state`,
  `/healthz`; rows older than `DASHBOARD_STALE_SECONDS` show as STALE.
- **Host port.** The static repo file defaults `DASHBOARD_PORT` to 8080. edge-api writes
  `DASHBOARD_PORT=${SSM_ONPREM_DASHBOARD_PORT}` (default **1881**) into `.env.onprem`, so
  edge-api-deployed boxes serve the board on 1881. `GET connect` / `POST webui` forward to
  that port for on-prem tenants and to Node-RED 1880 otherwise.

**What is generated vs out of band.** `deploy-onprem` now overwrites
`compose.onprem-edge.yml` with the edge-api-rendered one (`shared/onprem-compose.ts`) and
writes `.env.onprem` (`TENANT`, `DASHBOARD_PORT`, `AGENT_INGEST_API_KEY` = edge-api's
`SSM_EDGE_INGEST_KEY` or `__SET_ME__`). The **source tree** (`services/sparkplug-decoder`),
`configs/mosquitto/`, `onprem/agent.yaml` and `onprem/client.yaml` must already be in
`/opt/packiot/fatedge`; edge-api does not distribute them.

**Teardown** (`teardownOnpremStack`): `docker compose … down -v || true`, then
`rm -rf` of `onprem/`, `services/`, `configs/`, `*.tar.gz`, `.env.onprem` and the compose
file. The dir is guarded to a non-root absolute path.

### Edge-operator (ADR-0054 Option A, operate offline)

Opt-in with `descriptor.operator_edge = true` (`GET/POST /api/onboarding/operator-edge`,
audit event `onboarding.operator-edge`); the generated compose then adds:

| Service | Image | Ports | Env |
|---|---|---|---|
| `operator-edge` (container `onprem-operator`) | `${OPERATOR_EDGE_IMAGE:-ghcr.io/packiot/operator-edge:staging}` built from `operator/Dockerfile.edge` | `${OPERATOR_PORT:-8081}:80` | `EDGE_API_UPSTREAM` (default `https://edge.api.staging.packiot.app`), `REFDATA_UPSTREAM` (default `https://read.api.staging.packiot.app`), `NGINX_ENVSUBST_FILTER=^(EDGE_\|REFDATA_)` |

A `barcode-edge` service (`${BARCODE_PORT:-8082}`, `BARCODE_EDGE_API_KEY` = the tenant's
`enterprises.api_key`) is added the same way when the descriptor enables it.

How the operator survives an outage today:

| Concern | Mechanism | Status |
|---|---|---|
| Reads | nginx in the container caches `GET /v1/*` (`proxy_cache_valid 200 30s`, `proxy_cache_use_stale error timeout http_500..504`, `max_size=100m inactive=30d`). **GET only**: the SPA's reachability probe is a `HEAD`, so it still reaches the upstream and detects the outage | Shipped (`operator/nginx.edge.conf.template`) |
| Writes | The [operator app](operator-app.md) durable write-queue (IndexedDB, `VITE_PO_WRITE_QUEUE_ENABLED=true` baked into the edge image) buffers per tablet and replays with an `Idempotency-Key` | Shipped |
| Box-wide write outbox | `internal/writeforward`: forward to cloud; a 4xx is returned (never queued); transport error or 502/503/504 ⇒ persist to the SQLite outbox and return `202 {queued:true}`; `DrainOnce` replays FIFO, preserving `Idempotency-Key`, `X-Api-Key`, `Content-Type`, `Authorization` | **Engine only.** No `cmd/` binary imports it; not deployed |
| Local PO authority (Option B) | Local Postgres + bidirectional sync | Design only, gated on the PLC command channel (C1) |

!!! warning "Unverified"
    `nginx.edge.conf.template` injects `x-api-key: ${EDGE_API_KEY}` on `/api` and
    `${REFDATA_API_KEY}` on `/v1`, but the generated `operator-edge` service passes neither
    variable. How edge-operator requests authenticate on a live box has not been re-checked.

## Data & invariants

- **Cloud is the system of record.** The on-prem stack never writes to the cloud; the
  edge-operator (Option A) never owns PO state.
- **The primary path is never slowed by the tee.** The local target is best-effort, one
  attempt, no spool.
- **Generated files win.** Every deploy rewrites the generated files (except `.env`, which is
  write-once). A hand edit on the box is lost on the next Go-live, and a *stale* generated file
  on the box stays stale until a deploy regenerates it.
- **No secrets in artifacts by default.** Missing keys are rendered as `__SET_ME__` and
  reported as a gap.

## Observability

- Box Ops `GET status/detailed` and `GET health` (agent `/healthz`).
- Reader logs (`docker compose logs reader`): `start: group=… backlog=N`,
  `POST failed after N attempts (spooling)`, `spool: replayed N buffered batch(es)`,
  `spool full — dropped N oldest`, `local tee POST failed (ignored)`.
- Cloud side: `sparkplug_agent_http_ingest_total{outcome}` on the shared agent and the
  nginx access log for `:8449` (per-box egress IP).
- On-prem: dashboard `/healthz`; transformer `/healthz` on 9102.

## Failure modes

| Failure | Symptom | Cause | Fix |
|---|---|---|---|
| Floor dashboard blind, cloud fine (Bispharma, 2026-09-02, ~4 h) | `current_state` empty, reader logs `local tee POST failed`, then 401 | (1) reader and agent in different compose networks, so `127.0.0.1:9104` inside the reader was its own netns; (2) tee sent the cloud `INGEST_KEY` instead of `AGENT_INGEST_API_KEY` | Codified in reader-gen: `network_mode: host` for on-prem readers and a local target with `ingest_key_env: AGENT_INGEST_API_KEY` |
| No data after a descriptor prefix change (Bispharma, 2026-09-02) | Doubled topic names, capture step blank | Box `onprem/agent.yaml` and cloud tenant yaml kept the old `packml_topic` | Regenerate and redeploy every derived artifact together |
| Go-live "succeeds" but the reader keeps old tags | Old metrics still posted | `up -d` did not restart a container whose only change was a bind-mounted config | Deploy uses `--force-recreate` (fixed in `deployCommand`) |
| Box never registers | Not listed in SSM | No internet egress (e.g. a public subnet without a public IP) or activation expired (24 h) | Fix egress; mint a new activation |
| User-data never ran on a test EC2 box | Box silent | IMDS disabled also disables user-data delivery (sandbox provisioning, 2026-09-16→20) | Keep IMDS on for provisioning |
| `webui` 502 on a test box | StartSession denied | Box is `i-…` not a hybrid `mi-…` | Register it with an activation |
| Sparse cloud coverage for a live box (Bispharma, 2026-09-22) | ~40 % of posts missing, 0 unmapped | Lossy box → cloud link, not the pipeline | Check reader spool/backlog and box connectivity before debugging the cloud |
| Last batch lost on power cut | Small gap | Spool write is not fsync'd (noted 2026-09-02) | Accepted risk |
| Heavy docker ops on the shared staging app box (2026-09-16) | Docker API hangs | Sim "boxes" were dind containers on the app box | Never do large commits / storage-driver changes / restart churn there; re-onboard sim boxes instead of restarting them |

## Operating it

- **Onboard a box:** csadmin Box Ops → *Mint activation* → put the code in
  `/opt/packiot/edge-ssm.env` → `systemctl start ssm-register.service` → *Bootstrap* →
  *Deploy bundle*. For the cloud side, *Apply agent config* so the shared agent knows the
  tenant's group.
- **Manual on-prem bring-up:** `cd /opt/packiot/fatedge && docker compose -f
  compose.onprem-edge.yml --env-file .env.onprem up -d --build`.
- **Safe:** `restart`/`logs`, redeploying the bundle (`.env` preserved), restarting the
  on-prem stack (cloud unaffected). **Unsafe:** deleting `./spool` during an outage; running
  a second PLC reader against the same fragile S7 PLCs; any mutating op on the live CPACK box
  without the client's window.
