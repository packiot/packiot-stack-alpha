# CPACK → new-production topology seed (runbook)

**Purpose:** stand CPACK up **ready-but-empty** on new-production (`packiot`, F3-native)
so it can receive real CPACK SparkPlug data. New-prod uses the **legacy name-parse**
decode path (`BIRTH_BOUND_ROUTING` default-off) — the proven path for CPACK's real
stream — so this needs only topology + ingress, none of the ADR-0046 birth-bound machinery.

## What was done (2026-07-30)
- New-prod verified **empty** (0 enterprises/equipments/register).
- `OPERATOR_API_KEY` set in new-prod `/opt/packiot/.env` (ingress prerequisite + fixes the
  operator-adapter secret gap from the env review).

## The seed
Generated by **replicating staging ent-3 CPACK** (the proven topology) from
`packiot_analytics`, FK-ordered + idempotent, via `to_json`/`json_populate_record` (portable,
type-safe, column-order-independent; no `pg_dump` — it's blocked by Hasura on this stack):

```sql
-- per table, in FK order:
SELECT string_agg('INSERT INTO <t> SELECT * FROM json_populate_record(NULL::<t>, '
  || quote_literal(to_json(row)::text) || ') ON CONFLICT DO NOTHING;', E'\n')
FROM <t> WHERE id_enterprise = 3;   -- (shift_hours joins shifts)
```

**Artifact:** `s3://packiot-staging-db-backups-639178078294/cpack-newprod-topology-seed.sql`
(~1.0 MB — the size is legit: each `equipments` row embeds the stop-reason taxonomy JSON).

**Verified structure** (641 inserts, exact match to the source inventory):

| table | rows | | table | rows |
|---|---|---|---|---|
| enterprises | 1 | | packml_register | 137 |
| sites | 1 | | shifts | 15 |
| areas | 5 | | shift_hours | 420 |
| equipments | 62 | | | |

FK order = enterprises → sites → areas → equipments → packml_register → shifts → shift_hours.
`lead_machine`/`id_unit` are non-FK ints; the `id_equipment` self-FK is self-satisfying; so
row-by-row insertion in this order is safe (no deferral needed). `ON CONFLICT DO NOTHING`
makes re-apply a no-op.

## Apply (the gated step — do with dashboards up, before CPACK data lands)
1. Snapshot the new-prod DB volume (rollback net).
2. On the new-prod app node (`i-02d255a1c21fb1da3` → prod DB via pgbouncer):
   ```
   aws s3 cp s3://packiot-staging-db-backups-639178078294/cpack-newprod-topology-seed.sql /tmp/seed.sql
   docker run --rm --network stack_packiot-net -v /tmp/seed.sql:/s.sql:ro -e PGPASSWORD=… \
     postgres:15-alpine psql -h pgbouncer -U postgres -d packiot -v ON_ERROR_STOP=1 -f /s.sql
   ```
3. Verify: `SELECT count(*) FROM equipments WHERE id_enterprise=3;` → 62; register → 137.
4. Apply the packml_register `device_key` backfill (as staging: `UPDATE … SET device_key =
   replace(packml_topic,'/','-')`) if refdata resolve-by-device_key is ever wanted on prod.
5. Enable the `client-ingest` profile on new-prod (edge-transformer + ingest-shim +
   operator-adapter) → they start and receive CPACK's stream.
