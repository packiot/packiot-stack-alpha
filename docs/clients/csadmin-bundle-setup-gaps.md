# CS Admin — bundle-setup completeness tracker

What CS Admin must let a Customer Success engineer configure so the generated edge
bundle is **complete and correct without any hand-patching**. Derived from taking the
first real config-as-data client (CPACK) live end-to-end. The bundle is generated by
`generate-client-bundle.yml` from the tenant's `client_descriptors` row (DB, turnkey
#738) → so every field below must be settable via CS Admin and land in that descriptor.

Legend: ✅ built · 🟡 partial / verify · ⬜ missing (needs building).

## Fields CS Admin must own

| # | What | Descriptor path / target | Status | Notes |
|---|------|--------------------------|--------|-------|
| 1 | **PLC connections** — per endpoint: protocol (s7/modbus/opcua), host/IP, port | `plc.endpoints[].host_ref` / `endpoint_url_ref` | 🟡 | PR #11 `connections-editor` (csadmin claude-version) edits these; **verify it's deployed** + writes real hosts to the DB descriptor (generator #738 prefills `PLC_HOST_*` from them). |
| 2 | **Counters-only OEE** — a "counter-only line (no MachSpeed sensor)" toggle + a **rated speed (parts/min) per machine** | drives `COUNTERS_ONLY_OEE_ENABLED` + `COUNTERS_ONLY_IDEAL_RATES` | ⬜ | **BIGGEST NEW GAP (G4).** Without it, a Modbus/S7 counter-only client silently produces **ZERO OEE** (Calc's glitch guard drops every counter). Today rates come from `equipments.production_speed`; CS Admin must expose that field + the toggle. Ideally the decoder reads the rates from the DB at boot so edits flow automatically. |
| 3 | **count_index per member** (the PLC channel index) + confirmed/inferred state | `plc.endpoints[].members[].count_index` | 🟡 | The ADR-0045 onboarding CAPTURE step (observe live PLC indices → confirm). csadmin onboarding UI has capture (session 96); **verify** confirmed/inferred is visible + that cutover is gated on all-confirmed. CPACK still carries ~20 inferred (works in draft, blocks `--cutover`). |
| 4 | **Connectivity model** — `edge_model`: `nodered` (generated Node-RED reader) vs `reader` (Go PLC readers) | bundle input / descriptor | ⬜ | Currently a workflow_dispatch input; CS Admin should choose it (most clients = `nodered`). |
| 5 | **Deploy target** — production vs staging (selects CA namespace + ingest host) | bundle input | ⬜ | CS Admin should set/confirm; defaults to production. |
| 6 | **Generate + download + retry bundle** in the UI | — | 🟡 | Added session 96/97 (download-from-csadmin + retry). **Verify** it triggers `generate-client-bundle.yml` and surfaces the artifact link. |
| 7 | **Per-client customizations** (custom Node-RED nodes on the reader) | reader-gen "customizations" tab | 🟡 | PR #705 added a customizations tab in reader-gen; confirm CS Admin can attach them. |
| 8 | **uplink_broker** default = cloud ingest `ssl://<host>:8883` | `agent.uplink_broker` | ✅/⬜ | Fixed in the DB descriptor + committed file (F2, #743); make it a **generator default** so it's never `tcp://mosquitto:1883` (internal) for a real client — not a per-field CS Admin concern, but must never require manual fixing. |
| 9 | **Ingest API key** — auto-generated at bundle time | `AGENT_INGEST_API_KEY` | ✅ | #738 auto-gens it; no CS Admin field needed. |

## The one that bites hardest
**#2 (counters-only + rated speed).** Every other field just shapes connectivity; this
one is the difference between OEE flowing and a silent zero. Any Modbus/S7 client with
no speed sensor MUST have it set at onboarding. Make CS Admin:
1. detect / let the engineer flag "counter-only line", and
2. require a rated speed per counting machine (→ `production_speed`),
then the generator/decoder wires `COUNTERS_ONLY_*` automatically.
